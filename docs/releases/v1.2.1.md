## CaseHUD 1.2.1

Korrekturen für Programmstart, Kühlung und Gerätesuche.
*Fixes for program start, cooling and device detection. English below.*

### Änderungen
- **Programmstart:** Läuft CaseHUD schon, beendet sich ein weiterer Start sofort. Starts aus dem Autostart (`--minimized`, `--background`) zeigen dabei kein Fenster mehr, sondern schreiben nur eine Zeile in `casehud-start.log`. Kann die Sperre gegen Mehrfachstarts nicht angelegt werden, endet der Start sofort, statt zu warten
- **Kühlung – Hinweis zur Sensorquelle:** Kommen die Sensorwerte nicht vom CaseHUD-Sensordienst, sondern von einer anderen Quelle (z. B. einem selbst eingestellten Hardware-Monitoring), sagt die Kühlungsseite jetzt, warum nicht geregelt wird: Diese Werte dienen nur der Anzeige, die Lüfter bleiben auf sicherer Drehzahl. In der API stehen dazu `sensorsDisplayOnly` und `sensorSource`
- **Kühlung – Pumpenanschlüsse:** Wechselt die Zuordnung der Pumpen am Mainboard, gibt CaseHUD nicht mehr benötigte Anschlüsse sofort frei. Schlägt das Halten eines Anschlusses fehl, bleibt die bisherige Zuordnung bestehen
- **Kühlung – Beenden:** Nach dem Beenden baut CaseHUD die Kühlung nicht mehr neu auf
- **Gerätesuche:** Ist ein Gerät nicht angeschlossen (z. B. kein 8.8"-Display), steht nicht mehr alle 30 Sekunden ein Fehler im Log
- **API-Dokumentation:** Der Status `halted` und alle Alarmcodes der Kühlung sind in `/api/v1/openapi.json` und `docs/API.md` beschrieben

### Installation
`CaseHUD-Setup-1.2.1.exe` herunterladen und ausführen; eine bestehende Installation wird aktualisiert, Einstellungen bleiben erhalten. Alternativ gibt es eine portable ZIP; das Update direkt aus CaseHUD ist ebenfalls möglich. Hinweise zu dauerhaften Schreibvorgängen im Gerät und zum Haftungsausschluss: siehe Release Notes 1.0.0.

> ⚠️ Nutzung auf eigene Gefahr. Eine falsch eingestellte Kühlung kann Hardware überhitzen. CaseHUD ist ein privates Community-Projekt und steht in keiner Verbindung zu Lian Li.

### English

**Changes**
- **Program start:** when CaseHUD is already running, another start ends at once. Starts from autostart (`--minimized`, `--background`) no longer show a window; they only write a line to `casehud-start.log`. If the single-instance lock cannot be created, the start ends at once instead of waiting
- **Cooling – sensor source hint:** when the sensor values come from a source other than the CaseHUD sensor service (e.g. a hardware monitor set up by hand), the cooling page now says why it does not regulate: these values are for display only and the fans stay at their safe speed. The API reports this as `sensorsDisplayOnly` and `sensorSource`
- **Cooling – pump headers:** when the pump assignment on the mainboard changes, CaseHUD releases headers it no longer needs at once. If holding a header fails, the previous assignment stays
- **Cooling – exit:** after exit CaseHUD no longer rebuilds the cooling
- **Device detection:** when a device is not connected (e.g. no 8.8" display), the log no longer shows an error every 30 seconds
- **API documentation:** the `halted` state and all cooling alarm codes are described in `/api/v1/openapi.json` and `docs/API.md`

**Installation**
Download and run `CaseHUD-Setup-1.2.1.exe`; an existing installation is updated and keeps its settings. A portable ZIP is available too, and the update can also be installed from within CaseHUD. For permanent device writes and the disclaimer see the 1.0.0 release notes.

> ⚠️ Use at your own risk. Misconfigured cooling can overheat hardware. CaseHUD is a private community project and is not affiliated with Lian Li.
