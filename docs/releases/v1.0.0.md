## CaseHUD 1.0

Hardware-Dashboards für die Displays in deinem Gehäuse, ohne Abo und ohne Zusatzsoftware: Rotation, Szenen und Automatik, animierte Hintergründe, AWTRIX-Pixeluhren, das Breit-Display Universal Screen 8.8" und eine stabile API für externe Programme.
*Hardware dashboards for the displays in your case, no subscription and no extra software: rotation, scenes and automation, animated backgrounds, AWTRIX pixel clocks, the wide Universal Screen 8.8" and a stable API for external programs. English below.*

### Wichtig
- **Dauerhafte Schreibvorgänge im Gerät:** Nach der Zustimmung zum Haftungsausschluss schreibt CaseHUD **einmalig sein Logo als Start- und Ruhebild in jede UNI FAN TL LCD** (Flash des Lüfters, standardmäßig an, abschaltbar unter Einstellungen → Geräte). Eine Seriennummer für Lüfter-Displays ohne eine wird nur vergeben, wenn du es dort einschaltest (standardmäßig aus); vorhandene Seriennummern werden nie geändert. Auch Helligkeit und Drehung können im Gerät gespeichert werden; CaseHUD schreibt sie nur bei echten Änderungen. Diese Werte bleiben nach einer Deinstallation im Gerät.
- **Keine Geräteausgabe vor deiner Zustimmung:** Beim ersten Start erscheint der Haftungsausschluss; bis du zustimmst, sendet CaseHUD nichts an Geräte. Beleuchtung und experimentelle Geräte brauchen zusätzlich je einen einmaligen Hinweis.

### Funktionen
- **Displays:** Lian Li UNI FAN TL LCD (400×400, rund, bis 30 fps) und **Universal Screen 8.8" (1920×480, WinUSB):** Querformat, Software-Drehung, hochkant montierbar (90°/270°), automatische Wiederverbindung
- **Aufteilung für Breit-Displays:** Das Display lässt sich in Felder teilen (4, 3, 2, 2+4, 1+6 oder 8); jedes Feld ist ein virtuelles Display mit eigenem Design, Theme und Hintergrund. Dazu breite Designs („Dashboard (wide)“, Viererreihen pro Set)
- **Designs:** Sets Clean, Neon, Retro und Cyberpunk, jeweils Dark & Light, mit CPU+GPU-Kombi und Gaming-Designs (FPS, Frametime, Latenz); Uhren in allen Sets, weiche Animationen; Editor, Import/Export, **Community-Galerie**
- **Animierte Hintergründe** hinter Designs (Effekte, GIF/Bild/Video, Bloom), Hintergrund als eigener Block
- **Rotation:** Szenen oder Förderband durch die Displays, Übergänge, Kaskade
- **Szenen und Automatik:** Szenen bleiben getrennt von der Rotation; Regeln (ein beliebiges oder ein bestimmtes Spiel) schalten automatisch eine Szene und danach zurück (3 s Einschalt-, 10 s Ausschaltverzögerung). Gaming-Szene mit einem Klick
- **Spielerkennung:** Vordergrund-Programm, Vollbild oder Flip-Pfad, eingebaute Liste normaler Programme und eigene Ignorierliste („Kein Spiel“)
- **FPS über PresentMon** (inkl. Frame Generation / DLSS-Faktor), RTSS als Fallback
- **Eingebauter Sensor-Dienst** auf Basis von LibreHardwareMonitor, inkl. Fix für den ASUS-ROG-STRIX-X870(E) **T_Sensor** (Wassertemperatur)
- **AWTRIX-Pixeluhren** als Display: Netzwerksuche, AWTRIX 3 und AWTRIX NG, Ulanzi TC001 und TC002 mit eigenen Icons
- **Stabile API v1** (`/api/v1`, siehe `docs/API.md`) für externe Programme: Status, Displays, Designs, Szenen, Rotation, Automatik, Strom, Gaming-Hinweis, Server-Sent Events; Erkennung über `api.json` mit Token pro Start; `--background` und `--no-tray`
- Optionale **MCP-Schnittstelle** (standardmäßig aus)
- **Beleuchtung (optional, standardmäßig aus):** Tab „Beleuchtung“ für den UNI FAN TL Controller, ARGB-Anschlüsse und Onboard-Licht von ASUS-Mainboards, RAM (nur über die optionale SMBus-Brücke) und den LED-Rahmen des Universal Screen 8.8". Der TL Controller speichert jeden Lichtbefehl in seinem Flash; CaseHUD sendet daher nur bei echten Änderungen und empfiehlt die Synchronisation mit dem Mainboard
- **Herstellersoftware:** CaseHUD erkennt Programme, die dieselben Displays oder LEDs ansteuern, und fragt, ob es sie beenden soll (nur auf Klick, nur bekannte Programme)
- **Firmware:** Versionen der Geräte werden angezeigt; die Prüfung auf neuere Versionen ist optional und standardmäßig aus (liest nur die Download-Seite des Herstellers, dabei sieht der Hersteller deine IP-Adresse). CaseHUD installiert keine Firmware
- **Universal Screen 8.8" im Monitor-Modus:** „Zurückholen“-Knopf, falls die Herstellersoftware das Display umgeschaltet hat
- **Experimentelle Geräte** (standardmäßig aus, Einstellungen → Geräte, Tester gesucht): HydroShift/Galahad II LCD, Vision-M 9.2", Lancool 207 Digital, SL V3 / TL V2 LCD, TL/SL-INF Flex LCD und die Temperatursensoren des EdgeHub Advanced; Kühlmittel- und Pumpenwerte der Pumpenköpfe erscheinen als Sensoren. Die Treiber sind nach einer festen Geräteschnittstelle aufgebaut (`docs/DRIVERS.md`)
- Displays aus bei Bildschirmschoner, °C/°F, 12/24 h, globale Lüfternummern mit Identify-Screen, Display-Namen, Hotplug und Wiederverbindung
- Live-Vorschau im Fenster, einklappbare Design-Sets, Modus „HUD · Medien · Aus“; Fenster merkt sich Größe, Position und Maximierung
- Update-Hinweis (standardmäßig an, abschaltbar); alle Netzwerkzugriffe sind in der README unter „Netzwerk und Datenschutz“ aufgelistet

### Sicherheit
- **Signierte Prüfsummen:** `SHA256SUMS.txt.sig` (ECDSA P-256) liegt bei; der öffentliche Schlüssel steht in `docs/release-signing.pub.pem`, die Prüfung ist in `SECURITY.md` beschrieben
- API v1: nur localhost, Token pro Start (`api.json` mit geschützter Zugriffsliste), Host-Header-Prüfung, Request-Body auf 1 MiB begrenzt (413), unbekannte Felder werden abgelehnt, Limit für gleichzeitige Event-Streams
- Limits für Szenen, Regeln und Medien-Dateinamen
- `ProgramData\CaseHUD` ist für normale Benutzer nur lesbar

### Hinweise
- **SMBus-Brücke:** Der Sensor-Dienst enthält eine optionale, eng begrenzte Brücke (Named Pipe) für die RAM-Beleuchtung. Sie ist **standardmäßig aus**; siehe `docs/SMBUS-BRIDGE.md`
- **Startbild der Lüfter-LCDs:** erscheint, wenn CaseHUD nicht läuft; unter Einstellungen → Geräte abschaltbar, dort auch „Erneut schreiben“. Details: `docs/DRIVERS.md`
- Die experimentellen Geräte sind auf keiner echten Hardware bestätigt; Rückmeldungen über das Formular „Hardware-Testbericht“ sind willkommen. WinUSB-Displays (Universal Screen) und Wireless-Lüfter brauchen weiter Tester; AWTRIX wurde bisher vor allem mit simulierten Uhren getestet
- Die Programme sind noch nicht code-signiert, Windows SmartScreen kann warnen

### Installation
`CaseHUD-Setup-1.0.0.exe` herunterladen und ausführen. Das Setup installiert CaseHUD, den Sensor-Dienst, PawnIO und PresentMon. Alternativ gibt's eine portable ZIP.

Voraussetzungen: Windows 10/11 x64, WebView2-Runtime (bei Windows 11 dabei). Werden Sensoren nicht angezeigt? Der Sensor-Dienst schreibt ein Log nach `C:\Program Files\CaseHUD\sensors\sensors.log`.

> ⚠️ Nutzung auf eigene Gefahr. CaseHUD ist ein privates Community-Projekt und steht in keiner Verbindung zu Lian Li.

### English

**Important**
- **Permanent writes to devices:** after you accept the disclaimer, CaseHUD writes **its logo once as start and idle image into each UNI FAN TL LCD** (fan flash, on by default, switchable under Settings → Devices). A serial number for fan displays that have none is only assigned if you switch that on (off by default); existing serial numbers are never changed. Brightness and rotation may also be stored in the device; CaseHUD writes them only on real changes. These values stay in the device after uninstalling.
- **No device output before your consent:** the disclaimer appears at first start; until you accept, CaseHUD sends nothing to devices. Lighting and experimental devices need one more one-time notice each.

**Features**
- **Displays:** Lian Li UNI FAN TL LCD (400x400, round, up to 30 fps) and **Universal Screen 8.8" (1920x480, WinUSB):** landscape, software rotation, upright mounting (90/270 degrees), automatic reconnect
- **Split wide displays:** fields (4, 3, 2, 2+4, 1+6 or 8) that each act as a virtual display with their own design, theme and background; wide designs
- **Designs:** Clean, Neon, Retro and Cyberpunk sets in dark and light, CPU+GPU combos and gaming designs (FPS, frametime, latency), clocks in every set, smooth animations, editor, import/export, **community gallery**
- **Animated backgrounds** (effects, GIF/image/video, bloom), background as its own block
- **Rotation:** scenes or a conveyor through the displays, transitions, cascade
- **Scenes and automation:** scenes are kept separate from the rotation; rules (any game or a specific game) switch to a scene and back (3 s in, 10 s out); one-click gaming scene
- **Game detection:** foreground program, fullscreen or flip path, built-in list of desktop software plus your own ignore list
- **FPS via PresentMon** (incl. frame generation / DLSS factor), RTSS as fallback
- **Built-in sensor service** based on LibreHardwareMonitor, incl. a fix for the ASUS ROG STRIX X870(E) **T_Sensor** (water temperature)
- **AWTRIX pixel clocks** as displays: network search, AWTRIX 3 and AWTRIX NG, Ulanzi TC001 and TC002 with their own icons
- **Stable API v1** (`/api/v1`, see `docs/API.md`) for external programs: status, displays, designs, scenes, rotation, automation, power, gaming hint, server-sent events; discovery via `api.json` with a per-run token; `--background` and `--no-tray`
- Optional **MCP interface** (off by default)
- **Lighting (optional, off by default):** "Beleuchtung" tab for the UNI FAN TL controller, ARGB headers and onboard lighting of ASUS mainboards, RAM (only through the optional SMBus bridge) and the LED frame of the Universal Screen 8.8". The TL controller stores every light command in flash, so CaseHUD sends only real changes and recommends syncing with the mainboard
- **Vendor software:** CaseHUD detects programs that control the same displays or LEDs and asks whether to close them (on click only, known programs only)
- **Firmware:** device versions are shown; the check for newer versions is optional and off by default (reads only the manufacturer's download page, which sees your IP address). CaseHUD never installs firmware
- **Universal Screen 8.8" in monitor mode:** a "Bring back" button if vendor software switched the display
- **Experimental devices** (off by default, Settings -> Devices, testers wanted): HydroShift/Galahad II LCD, Vision-M 9.2", Lancool 207 Digital, SL V3 / TL V2 LCD, TL/SL-INF Flex LCD and the EdgeHub Advanced temperature sensors; coolant and pump readings of the pump heads show up as sensors. Drivers follow a fixed device interface (`docs/DRIVERS.md`)
- Displays off during the screen saver, °C/°F, 12/24 h, global fan numbers with an identify screen, display names, hotplug and reconnect
- Live preview, foldable design sets, mode "HUD / Media / Off", remembered window geometry, update notice (can be switched off)

**Security:** signed checksums (`SHA256SUMS.txt.sig`, ECDSA P-256, public key in `docs/release-signing.pub.pem`, see `SECURITY.md`); API v1 is localhost-only with a per-run token, Host header check, 1 MiB body limit (413) and strict field checking; limits for scenes, rules and media names; `ProgramData\CaseHUD` is read-only for normal users.

**Notes:** The start image is shown when CaseHUD is not running (switchable under Settings → Devices, with a "Write again" button). The sensor service contains an optional, narrowly scoped SMBus bridge for RAM lighting (off by default, see `docs/SMBUS-BRIDGE.md`). The experimental devices are not confirmed on real hardware yet (reports via the hardware test report form are welcome); WinUSB displays and wireless fans still need testers; AWTRIX has mostly been tested against simulated clocks. Executables are not code-signed yet, so SmartScreen may warn.

Download and run `CaseHUD-Setup-1.0.0.exe`; it installs CaseHUD, the sensor service, PawnIO and PresentMon. A portable ZIP is available too. Requires Windows 10/11 x64 and the WebView2 runtime (included in Windows 11).

> ⚠️ Use at your own risk. CaseHUD is a private community project and not affiliated with Lian Li.
